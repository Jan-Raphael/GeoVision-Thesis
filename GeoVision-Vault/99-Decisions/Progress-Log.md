Three things beyond the spec. Two findings worth recording. First, **the vault contradicted itself**: [[Device-Pairing-Protocol]] said store the device secret *hashed* and also verify with `HMAC_SHA256(device_secret, …)` — impossible, because a MAC key must be recoverable. Second, the advisory lock guarding sequence allocation keyed on Python's `hash()`, which is **randomised per process** — two uvicorn workers would have taken different locks and serialised nothing, so two images would share a filename and one would silently overwrite the other in storage. Invisible to every single-process test; fixed with a stable digest and pinned to a literal (ADR-022). Also: `GV_JWT_SECRET_KEY` must be set explicitly when running uvicorn locally — the ephemeral fallback is generated per process, and uvicorn's Windows launcher imports the app more than once, so tokens get signed and verified with different keys. | [[Module-06-AI-Preprocessing]] — pure OpenCV/Albumentations, no server or dataset dependency. |
