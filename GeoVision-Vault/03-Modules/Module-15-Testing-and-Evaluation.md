# Module 15 — Testing, Evaluation & Thesis Artifacts

## Scope
Harden the test suite and generate **every number and figure** the manuscript needs.
Measurement plan lives in [[Evaluation-Plan]]; this note is how it gets executed.

## Test pyramid

| Level | Where | What | Target |
|---|---|---|---|
| Unit | `ai/tests/`, `backend/tests/unit/` | progress aggregator, preprocessing, naming, value objects, authorization, status derivation | **≥ 90 %** on `domain/` and `ai/progress/` |
| Integration | `backend/tests/integration/` | repositories on real Postgres, storage on MinIO, Celery tasks, HMAC ingest | every endpoint hit at least once |
| Contract | `tests/contract/` | OpenAPI schema vs the frontend's TS types | no drift |
| E2E | `tests/e2e/` (Playwright) | visitor journey, owner journey, pairing + live update | both journeys green |
| Load | `tests/load/` (k6/locust) | ingest throughput, API p95, 50 WS clients | meets the NFR table |
| Hardware | manual, logged | 72 h soak, offline buffering, battery curve | recorded in the thesis |

Overall coverage target: **≥ 80 %** backend, ≥ 70 % frontend. Coverage on the progress
algorithm and the permission layer matters far more than the aggregate number — those two are
where a bug is both likely and consequential.

## Evaluation artifacts to generate
- `ai/evaluation/run_all.py` — one command producing everything in `outputs/evaluation/`:
  1. classifier metrics table (per-class P/R/F1, macro-F1, ordinal error)
  2. confusion matrices (counts + normalized)
  3. training curves
  4. backbone comparison table + accuracy-vs-latency scatter
  5. ablation table
  6. calibration/reliability diagram
  7. YOLO mAP + PR curves + annotated samples
  8. classifier-vs-detector agreement table
  9. progress-algorithm accuracy vs the manual ground-truth curve
  10. raw-vs-smoothed series plot
  11. system latency + throughput summary
  12. battery/uptime plots from `device_events`
- `scripts/screenshot_dashboard.py` — Playwright captures of every page in a consistent
  viewport for the manuscript.
- `documentation/openapi.json` + a generated API reference.
- ERD export.

## Critical implementation notes
- **Every figure is script-generated.** A hand-edited chart cannot be regenerated when the
  model is retrained the week before submission — and it will be retrained.
- Tests must be **deterministic**: fixed seeds, frozen clock (`freezegun`), no real network.
- Integration tests get a **real Postgres** (testcontainers or a compose service) — SQLite
  will not exercise the enums, `citext`, arrays, or partial indexes this schema depends on.
- Fixtures build entities through factories (`factory_boy`), not hand-written dicts.
- Add a CI job asserting **TensorFlow is absent** from both lockfiles.
- Keep a small committed sample-image set so the AI tests run in CI without the full dataset.
- Record the exact hardware used for every latency number (CPU model, GPU, RAM); "210 ms" is
  meaningless without it.

## Dependencies
All prior modules. `pytest-cov`, `factory_boy`, `freezegun`, `testcontainers`, `playwright`,
`k6`/`locust`.

## How to run
```bash
pytest --cov=app --cov=ai --cov-report=html          # unit + integration
npx playwright test                                   # e2e
python -m ai.evaluation.run_all --classifier models/classifier/resnet18/v1/best.pt \
                                --detector models/detector/yolov8n/v1/best.pt
python scripts/screenshot_dashboard.py
k6 run tests/load/ingest.js
```

## Testing procedure (i.e. testing the tests)
1. Full suite green locally and in CI.
2. Coverage thresholds enforced in CI (build fails below them).
3. `run_all.py` on a clean checkout regenerates every figure without manual steps.
4. Deliberately break the ratchet logic → the corresponding unit test fails (the suite
   actually detects regressions, rather than merely passing).
5. E2E runs against a freshly seeded database, twice in a row, with the same result.
6. Load test meets the NFR targets in [[Master-Architecture]] §9.

## Expected output
`outputs/evaluation/` containing every table and figure the results chapter needs, plus a
green CI badge and a coverage report.
